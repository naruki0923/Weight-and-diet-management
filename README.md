# 体重・食事管理 Bot

食事の写真から Gemini がカロリーと PFC を算出し、Google スプレッドシートに記録する。
今日の合計と「目標まであと何 kcal か」を返す。

入力は **iOS ショートカット**（写真 → 共有 → タップ）、振り返りは **スプレッドシートのグラフ**（PC）。
設定の変更はスプレッドシートの「設定シート」を直接編集する。

LINE Bot は使わなくなったため削除した（コミット履歴には残っているので必要なら戻せる）。

## 構成

| ファイル | 役割 |
|---|---|
| `main.py` | FastAPI。ショートカット用の API |
| `summary.py` | 解析 → 記録 → 文面組み立て |
| `spreadsheet.py` | Google スプレッドシートの読み書き |
| `tdee.py` | BMR / TDEE / 推奨摂取カロリーの計算（シート非依存の純粋な計算） |
| `ai.py` | Gemini による画像解析とアドバイス生成 |
| `config.py` | 環境変数の読み込み |

## 環境変数（`.env`）

```
GEMINI_API_KEY=...
SPREADSHEET_URL_OR_KEY=<スプレッドシートのURL、またはURL中のキー>
GCP_SERVICE_ACCOUNT_JSON=credentials.json
API_TOKEN=<自分で決めた長い文字列>
```

`API_TOKEN` はショートカットから API を叩くときの合言葉。次のコマンドで生成できる。

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

`GCP_SERVICE_ACCOUNT_JSON` は **ファイルパスでも JSON 文字列そのものでも**よい。
ローカルは `service_account.json` を置いてパス指定、Vercel は中身を貼り付ける。

## デプロイ（Vercel）

1. このリポジトリを Vercel にインポートする（Framework Preset は `Other`）
2. Settings → Environment Variables に上記 4 つを登録する
   - `GCP_SERVICE_ACCOUNT_JSON` には `credentials.json` の**中身を丸ごと**貼る
3. デプロイすると `https://<プロジェクト名>.vercel.app` が払い出される

以降は `git push` するたびに自動デプロイされる。
`vercel.json` が全リクエストを `main.py` の FastAPI アプリに流している。

### デプロイが Blocked になるとき

Vercel はコミットの author email が GitHub アカウントに紐づいていないとデプロイを拒否する。
`git config user.email` が未設定だと `ユーザー名@ホスト名.local` が使われて弾かれるので、
GitHub の noreply アドレスを設定しておく。

```bash
git config --global user.email "<ユーザーID>+<ログイン名>@users.noreply.github.com"
```

ID は `gh api user --jq .id` で確認できる。

動作確認:

```bash
curl -H "X-API-Token: $API_TOKEN" https://<プロジェクト名>.vercel.app/today
```

## 腕立て伏せ（週 5 日 × 20 回 5 セット）

`20 回 × 5 セット` を 1 日のノルマ、それを **週 5 日**やるのが目標。
20 回やるたびにショートカットを叩くと 1 セット加算され、通知に
`腕立て 3/5セット` と `今週 2/5日` が出る。

- 記録先は **腕立て記録シート**（`日付 / セット数 / 回数 / 更新時刻`）。1 日 1 行。
  シートが無ければ初回アクセス時に自動で作られる。
- 週は **月曜はじまり**。5 セット達成した日だけを「今週の達成日」として数える。
- 回数やノルマを変えたいときは `config.py` の
  `PUSHUP_REPS_PER_SET` / `PUSHUP_SETS_PER_DAY` / `PUSHUP_DAYS_PER_WEEK` を書き換える。

## 1 日の区切りは朝 3 時

食事・体重・腕立てのすべてで、**朝 3 時を過ぎるまでは前日ぶん**として扱う。
深夜 1 時の夜食を翌日のカロリーに入れられると実感と合わないため。
`config.py` の `DAY_START_HOUR` で変えられる。

シートに残る日時はあくまで実時刻で、集計するときに 3 時間ぶん巻き戻して日付を決めている。

## TDEE（消費カロリー）の自動計算

体重を記録するたびに BMR / TDEE を計算し直し、**目標カロリーまで自動で書き換える**。
体重が増えれば必要カロリーも増えるので、手で直す必要がない。

計算式は **Harris-Benedict 改訂版**。活動係数は次のとおり。

| レベル | 内容 | 係数 |
|---|---|---|
| 1 | ほぼ運動しない（デスクワーク中心） | ×1.2 |
| 2 | 軽い運動（週 1〜3 日） | ×1.375 |
| 3 | 中程度の運動（週 3〜5 日） | ×1.55 |
| 4 | 激しい運動（週 6〜7 日） | ×1.725 |
| 5 | 非常に激しい運動（毎日＋肉体労働） | ×1.9 |

目標カロリーは `TDEE + 目標区分ぶんの増減`（増量 +300 / 維持 ±0 / 減量 −300、10 kcal 単位に丸め）。
`カロリー調整` を設定シートに入れると、その値が増減として優先される。

### 設定シートで使う項目

身体データは「設定シート」の A 列に項目名、B 列に値を書く。

| 項目名 | 例 | 内容 |
|---|---|---|
| `性別` | 男性 | |
| `年齢` | 20 | |
| `身長` | 168 | cm |
| `体重` | 49 | kg。体重記録シートに記録があればそちらが優先される |
| `活動レベル` | 2 | 1〜5（上の表） |
| `目標区分` | 増量 | 増量 / 維持 / 減量 |
| `カロリー調整` | 720 | TDEE への増減を直接指定。目標区分の既定値より優先 |
| `カロリー` | 2700 | 目標カロリー。`/weight` を叩くと自動で書き換わる |

**目標体重に達したら `目標区分` を `維持` に変え、`カロリー調整` を空にする。**
そのままだと増え続ける。

## API

いずれも `X-API-Token` ヘッダーに `API_TOKEN` を入れる。

| メソッド | パス | 内容 |
|---|---|---|
| `POST` | `/meal` | 画像を解析して記録し、結果と今日の合計を返す。下記の2通りで送れる |
| `GET` | `/today` | 今日の合計と残りカロリーを返す |
| `POST` | `/weight` | `{"weight": 55.2}` を送ると体重を記録し、TDEE と目標カロリーを再計算 |
| `GET` | `/tdee` | 今の身体データから BMR / TDEE / 推奨カロリーを返す |
| `POST` | `/tdee/apply` | 推奨カロリーを目標カロリーとして設定 |
| `POST` | `/pushup` | 腕立てを 1 セット記録し、今日と今週の進捗を返す（`?sets=2` でまとめ記録） |
| `GET` | `/pushup` | 今日のセット数と今週の達成日数を返す（記録は増やさない） |

### `POST /meal` の送り方

| 形式 | 内容 |
|---|---|
| `multipart/form-data` | `image` に画像、`note` に補足（省略可） |
| 生バイナリ | ボディに画像そのもの（補足なし） |

`note` は「大盛り」「半分残した」など**写真から読み取れない情報**を渡すためのもの。
分量は推定誤差の主因なので、指定があれば画像からの推測より優先させている。

解析は `response_schema` で構造を強制し、`temperature=0` で固定している。
これを入れる前は `memo` に生の引用符が混ざって JSON が壊れ、5回中3回失敗していた。

レスポンスの `message` に、そのまま通知に出せる文面が入っている。

```json
{
  "message": "🍽️ 鮭おにぎり\n⚡ 180 kcal（P 4 / F 1 / C 38）\n\n📊 今日の合計（2食）...",
  "meal": { "meal_name": "鮭おにぎり", "calories": 180, ... },
  "totals": { "calories": 1303.0, "protein": 28.0, ... },
  "target": 2700.0,
  "remaining": 1397.0
}
```

## ローカルで動かす

```bash
./venv/bin/uvicorn main:app --port 8123
```

```bash
curl -H "X-API-Token: $API_TOKEN" http://127.0.0.1:8123/today
```

`--reload` を付けるとワーカーが古い状態を掴んで 500 を返すことがあるので、
挙動を確かめたいときは付けずに起動し直すほうが確実。

## iOS ショートカットの作り方

### 食事を記録する

ショートカット App で新規作成し、以下を並べる。

1. **共有シートに表示** をオンにする（設定 → 受け取る内容を「イメージ」のみにする）
2. `URL の内容を取得`
   - URL: `https://<デプロイ先>/meal`
   - 方法: `POST`
   - ヘッダ: `X-API-Token` → `<API_TOKEN>`
   - 要求の本文: **ファイル** を選び、`ショートカットの入力` を指定
3. `辞書の値を取得` → キー `message`
4. `通知を表示` → さきほどの値

写真 App で写真を開き、共有 → このショートカットをタップすれば記録される。

### 今日の残りを確認する

1. `URL の内容を取得` → `https://<デプロイ先>/today`、`GET`、ヘッダに `X-API-Token`
2. `辞書の値を取得` → キー `message`
3. `通知を表示`

ホーム画面に追加しておくと 1 タップで見られる。

### 腕立てを 1 セット記録する

20 回やり終えるたびに叩くショートカット。ホーム画面に置いておく。

1. `URL の内容を取得` → `https://<デプロイ先>/pushup`、`POST`、ヘッダに `X-API-Token`
   - 要求の本文は空でよい
2. `辞書の値を取得` → キー `message`
3. `通知を表示`

進捗だけ見たいときは同じ URL を `GET` で叩く別ショートカットを作る（記録は増えない）。

### 体重を記録する（任意）

eufy Life アプリを開くとヘルスケアに同期されるので、そこから拾う。

1. `ヘルスケアのサンプルを検索` → 種類「体重」、並び替え「開始日 / 新しい順」、上限 1
2. `URL の内容を取得` → `https://<デプロイ先>/weight`、`POST`、ヘッダに `X-API-Token`
   - 要求の本文: **JSON**、キー `weight`（数値）にヘルスケアの値を入れる
3. `辞書の値を取得` → キー `message` → `通知を表示`

オートメーションで「毎朝 8:00」に実行すれば自動で入る。
このとき TDEE と目標カロリーも一緒に再計算されるので、`message` に新しい目標値が入って返る。

## ダッシュボード（スプレッドシート）

`ダッシュボード` シートに、体重 / 今日のカロリー / PFC / 腕立て の 4 ブロックとグラフ 3 つを置いている。
数字はすべて数式なので、シートを開けば最新になる（コードから書き込んではいない）。

| ブロック | 内容 |
|---|---|
| 体重 | 現在 / 7 日平均 / 週の変化率 / 増量ペースの判定 |
| 今日のカロリー | 残り / 摂取 / 目標 / 7 日平均 / 判定 |
| PFC の達成状況 | 実績・目標・達成率のバー、`P / 体重` の g/kg |
| 腕立て伏せ | 今日 `n/5セット` / 今週 `n/5日` / 直近 7 日の ✅⬜ / 連続達成 / 判定 |

グラフは体重の推移・摂取カロリーの推移・腕立てのセット数の 3 つ。
`P〜U` 列は計算用の補助列なので非表示にしてある。

集計元は `日別集計` シート（食事記録を日ごとに合計した表）と `腕立て記録シート`。
**日付はどちらも朝 3 時区切りの論理日付**で、`INT(日時 - 3/24)` で求めている。
シート側の数式には**ノルマの 5 セット / 週 5 日が直接書いてある**ので、
`config.py` の値を変えたときはダッシュボードの数式も直すこと。

## PC でグラフを見る

スプレッドシートに新しいシート（例: `日別集計`）を追加し、A1 に次を貼る。

```
=QUERY(
  {ARRAYFORMULA(LEFT(食事記録シート!A:A,10)), ARRAYFORMULA(IFERROR(食事記録シート!C:C*1,0))},
  "select Col1, sum(Col2) where Col1 <> '' group by Col1 order by Col1 label Col1 '日付', sum(Col2) '合計kcal'",
  0
)
```

日付ごとの合計カロリーが並ぶので、範囲を選んで「挿入 → グラフ」で折れ線にする。
目標ラインを引きたい場合は C 列に `=2300` を並べて系列に加える。

## シートの構造（注意点）

| シート | ヘッダー | 列 |
|---|---|---|
| 設定シート | あり | 項目名 / 設定値 / 単位 / メモ |
| 食事記録シート | **なし。1 行目からデータ** | 日時 / メニュー名 / カロリー / P / F / C |
| 体重記録シート | なし | 日時 / 体重 |
| 腕立て記録シート | あり | 日付 / セット数 / 回数 / 更新時刻 |
| 筋トレ記録シート | あり | 日付 / プランク / 腹筋 / 腕立て伏せ（旧仕様。未使用） |

シートごとにヘッダーの有無が違うため、`get_all_records()` は使わず
`get_all_values()` と列位置で読んでいる。

目標カロリーの項目名は `目標カロリー` ではなく **`カロリー`**（設定シート B3）。
B 列は桁区切り書式（`2,300`）なので、読むときはカンマを除去して数値化している。

TDEE 用に設定シートで使う項目名: `性別` / `年齢` / `身長` / `活動レベル` / `目標区分` / `カロリー調整`。
`体重` は体重記録シートの最新値を優先し、記録が 1 件もないときだけ設定シートの `体重` を見る。
`目標体重` と混同しないよう、これらは**項目名の完全一致**で読み書きしている。

## 既知の問題

- `筋トレ記録シート`（プランク / 腹筋 / 腕立て伏せ を「済」で埋める旧仕様）は使っていない。
  過去の記録として残してあるだけで、読み書きするコードはもうない。
- `google-generativeai` はサポート終了済み。いずれ `google-genai` へ移行が必要。
